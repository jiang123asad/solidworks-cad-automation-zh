# 执行、证据与恢复

统一入口 `scripts/cad_assistant.py` 通过 `shell=False` 与参数列表启动白名单脚本，不拼接用户输入为 shell 命令；每次调用选定一个后端，不自动安装、切换或重试 CAD 写操作。子进程中的 COM 按原脚本单线程调用，不跨线程传递 COM 对象。

## 会话范围

同一 Windows 用户的入口通过系统临时目录 `solidworks-cad-automation-session/` 的文件锁排他执行，包放在不同目录也共享此状态。锁由 OS 在入口退出时释放；`pending.json` 会保留运行状态。入口意外退出时，子进程可能继续运行，因此新入口看到 pending 仍会拒绝启动。

锁只协调本入口，不能控制其他用户、原始脚本、独立外部后端、鼠标键盘和人工 SW 操作。运行期间不要并行改动活动文档；待输入必须已保存且未在 SW 中打开。输入 SHA256 只能发现列出的文件在前后不一致，不能证明全部外部依赖或属性都被保护。

## 状态和证据

先写 `result.json` 与 pending，再启动脚本；记录子进程 PID，保留原始日志。执行后核对预期文件非空与已列出输入的 SHA256，将退出码、前后指纹及限制写入任务报告。输入被改动会判失败。

本地脚本退出成功不等于任意几何验证通过：倒角/密封锥沿用底层检查，导出只检查保存/文件生成，对比只是汇总指标。外部工程图以新输出目录中的固定审视报告读取 JSON，允许控制台有进度日志；报告缺失/无效或不明状态判为结果待确认；可审视输出始终标为需要人工检查，失败中间文件不能当成功交付。

## 不明结果不重做

入口等待子进程，不把等待超时包装成取消。Ctrl+C、入口关闭、异常退出码或外部输出不明时，写入/保留结果待确认；失败同样保留状态，以便核对部分产物。不会自动调用另一个后端补做，也不强杀 SW 或关闭用户文档。

恢复前查看报告、任务进程、SW 文档与可能生成的输出。确认执行已结束、源文件及结果已查清后运行 `cad_assistant.py resolve-pending --confirm 已核对SW状态`。记录 PID 仍存活时会拒绝恢复；PID 被系统复用时可能保守阻塞，请人工检查，不盲目删状态。恢复只归档 pending，不回滚几何。

若安装目录/临时目录被人工清空，会丢失部分会话证据；文件锁与任务记录不是通用事务系统，不能保证原生 CAD 多步操作自动回滚。
